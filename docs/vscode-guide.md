# ICS for VS Code: user guide

The Marketplace overview is a quick introduction. This guide covers the editor behavior, settings, commands, recovery files, and current language-service limits in more detail.

## Installation and first use

Install **ICS — Indented C#** from the VS Code Marketplace. To install a downloaded VSIX instead, open Extensions, choose **… → Install from VSIX…**, and select the package.

The converter is included in the extension. Microsoft's .NET Install Tool dependency installs and maintains the user-level .NET 10 runtime; a system-wide `dotnet` installation is not required. First use may need an Internet connection.

Open a `.cs` file, then run **ICS: Open C# as ICS** from the file's context menu or press **Ctrl+K I** (**Cmd+K I** on Mac). An editable ICS view opens beside the C# source.

## Preview edits, saves, and recovery

Both panes can be edited. After about 400 ms without typing, a successful C# edit refreshes ICS, or a successful ICS edit updates the paired C# **buffer**. These automatic updates do not by themselves write the source file to disk. **ICS: Apply Preview to C#** also validates and updates the C# buffer without saving it.

Incomplete input leaves the passive pane at its last verified version and marks the preview **out of date**. Once the input is convertible again, synchronization resumes. Rapid edits, undo, and redo use the latest editor state; closing the preview cancels pending conversions.

Saving a valid, synchronized ICS preview saves the paired C# file. Pro's `ics.autoSaveCSharpFromPreview` can save each successful update automatically, even when VS Code's `files.autoSave` is off. VS Code's own Auto Save still controls ordinary editor-buffer saves.

If both panes change independently, neither silently overwrites the other. Use **ICS: Resolve Preview Conflict** to review the versions and choose one. Conflict resolution keeps a local backup of both versions.

Saving an incomplete or conflicting preview stores a **local recovery draft**, not C#. The status tooltip says **Draft saved; C# not updated**. Reopening the same preview restores its latest active draft. Each VS Code window also retains its own latest snapshot for the source, so another window cannot erase its only recovery copy. Once synchronized C# is saved, the active draft and that window's snapshot are removed. Older-window snapshots and conflict backups remain for manual recovery; they are never silently merged.

Recovery snapshots and backups contain C# and ICS source text. They stay in the extension's local storage rather than beside the project files and are not uploaded. They are not encrypted by ICS. Run **ICS: Open Preview Recovery Folder** to inspect or delete retained files. See the [VS Code privacy notice](../privacy/vscode.md) for the data-retention details.

## Other workflows

With Pro, `ics.displayIcsOnly` replaces raw C# editors with ICS views while saves continue to write ordinary `.cs` files. **ICS: Toggle ICS View** switches the active file's view.

For standalone `.ics` files, **ICS: Sync Current File to C#** writes a paired `.cs` file with the same basename. **ICS: Generate C# for Workspace ICS Files** processes the workspace after confirmation. Pro's `ics.syncOnSave` automatically syncs a standalone file when saved. If a paired C# file exists and lacks the configured `<auto-generated` marker, the extension asks before overwriting it; `ics.protectUserCSharpFiles` controls that prompt.

**ICS: Export as ICS File** makes a one-time standalone `.ics` copy from C# (or another ICS file). Export does not create a live-linked preview.

## Language services and diagnostics

ICS editors provide semantic highlighting, hover, Go to Definition, Find References, completion, and reference-count code lenses. The language services analyze a generated C# projection locally. They do not currently load the containing `.csproj` and its references, so names declared in other project files or external assemblies may be unresolved. Results that require full project context can therefore be incomplete.

ICS parse errors and generated-C# diagnostics appear in Problems after a short pause. Because the diagnostic compilation lacks project references, some semantic diagnostics may be false positives. `ics.enableDiagnostics` defaults to `true`; setting it to `false` suppresses ICS diagnostics, including useful parse errors. We recommend trying it on your project before changing the default for yourself.

## Settings reference

Open VS Code Settings and search for **ICS**. Free live pairing works without configuration.

| Setting | Default | Effect |
| --- | --- | --- |
| `ics.syncOnSave` | `false` | Pro: sync standalone `.ics` to `.cs` on save. |
| `ics.displayIcsOnly` | `false` | Pro: replace `.cs` editors with editable ICS views. |
| `ics.autoSaveCSharpFromPreview` | `false` | Pro: save paired C# after each successful live update; in-memory pairing remains free. |
| `ics.protectUserCSharpFiles` | `true` | Ask before overwriting a C# file that does not look generated. |
| `ics.generatedFileMarker` | `<auto-generated` | Marker used to recognize generated C# files. |
| `ics.removeBraces` | `false` | Remove optional braces from regenerated C# where safe, such as those around a single-statement `if`. Structural braces already disappear in the ICS view without this setting. Braces needed for valid C#, scope, `else` binding or preprocessor structure are retained. Preview edits preserve C# outside the regenerated region exactly, although some edits require a larger enclosing region. |
| `ics.removeIfConditionParentheses` | `false` | Remove parentheses around eligible `if`/`else if` conditions in ICS. |
| `ics.matchLineNumbers` | `false` | Insert blank lines in ICS to align line numbers with C#. |
| `ics.tabWidth` | unset | Override spaces per logical tab stop; otherwise use nearest `.editorconfig` `tab_width`. ICS uses spaces. |
| `ics.enableDiagnostics` | `true` | Publish ICS parse and generated-C# diagnostics. |

Changing conversion settings refreshes open ICS previews. Settings are scoped to the file: a workspace setting will not apply to a file opened outside that workspace.

### Optional braces in regenerated C#

Structural C# braces disappear in the ICS view without enabling `ics.removeBraces`. Turning it on changes the C# you get back: when a preview edit is applied, optional braces—such as those around a single-statement `if`—are removed where safe within the regenerated region. Braces needed to preserve valid C#, scope, `else` binding or preprocessor structure are retained. C# outside that region is preserved exactly, although some edits require regenerating a larger enclosing region. The setting is off by default.

For example, start with this C#:

```csharp
if (ready)
{
    Send(1);
}
```

The ICS view already omits those braces with either setting:

```text
if (ready)
    Send(1)
```

With `ics.removeBraces` enabled, changing `if (ready)` to `if (!ready)` in the preview regenerates that `if` statement as:

```csharp
if (!ready)
    Send(1);
```

Opening an unchanged preview does not rewrite the original C#. An edit confined to `Send(1)` can preserve the surrounding `if` braces because they lie outside the regenerated region.

Shortcuts: **Ctrl+K I** (**Cmd+K I** on Mac) toggles ICS; **Ctrl+Alt+S** (**Cmd+Option+S**) applies a preview; **Ctrl+Alt+R** (**Cmd+Option+R**) refreshes a clean preview. VS Code's **Shift+Alt+F** (**Shift+Option+F**) invokes Format Document in ICS.

### Measuring server latency

Pause typing, start the measurement, use the editor normally, then pause and finish. Requests that overlap either boundary require a retry. The report separates pre-send startup/recovery waits from transport round trips. Its **non-execution latency** includes queueing, transport, and serialization; it is not an exact queue-wait measurement. Windows spanning a server restart are discarded, and mismatched or failed comparisons are marked unavailable. Only aggregate timings, method names, and counts are kept locally; no source text or paths are uploaded.

## Troubleshooting

If **Open C# as ICS** shows no preview, open VS Code's **Output** panel (`Ctrl+Shift+U`) and select **ICS Language Server**. Converter errors appear there. If automatic runtime installation fails, run **.NET Install Tool: Show Installation Log** and check network or proxy settings.

If diagnostics cite inaccessible or missing project symbols, see [Language services and diagnostics](#language-services-and-diagnostics). If conversion options do not apply, check whether the file is outside the workspace where you set them.
